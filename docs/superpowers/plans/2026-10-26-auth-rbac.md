# Auth & RBAC Implementation Plan

> **For agentic workers:** Implement this plan task-by-task. Keep changes surgical. Do not add dependencies or commit unless the user explicitly asks. Backend authorization is the security boundary; frontend guards are UX only.

**Goal:** Add email/password authentication with Sanctum SPA cookies and role-based access for `customer`, `store_owner`, and `admin`, then replace the storefront demo-auth switch with real session-aware UI.

**Architecture:** Laravel owns sessions, CSRF, credentials, roles, and authorization. The SPA sends credentialed requests with `X-XSRF-TOKEN`. TanStack Router guards a client-only pathless `_authenticated` shell using the shared session query. Public signup creates customers only.

**Tech Stack:** Laravel 13, Sanctum 4, Pest 4, React 19, TanStack Router/Query, Zod, Vitest.

---

## Acceptance Criteria

- [ ] Public signup creates only `customer` and auto-logs in.
- [ ] Login returns the authenticated user and establishes a Sanctum SPA session.
- [ ] Logout invalidates the session and clears the client cache.
- [ ] `GET /api/v1/auth/me` returns the current user or 401.
- [ ] Duplicate email returns 409; invalid credentials 401; validation 422; role denial 403; 6th login attempt/min/IP 429.
- [ ] `customer`, `store_owner`, and `admin` are modelled as a backed enum and never exposed as mass-assignable input.
- [ ] Session cookie is HttpOnly, SameSite=Lax, Secure in production; idle lifetime 7 days and absolute lifetime 30 days.
- [ ] Storefront header uses the real session and links guests to sign-in, customers to `/akun`, owners to `/toko`, admins to `/admin`.
- [ ] Demo-auth store, switch, and hook are removed from production code.
- [ ] Order history no longer asks for demo login; guests get a sign-in CTA, customers see orders, owners/admins get a role notice.
- [ ] Order status masks PII for guests and shows full PII for authenticated users.
- [ ] Backend Pest tests, frontend Vitest tests, typecheck, lint, and production build pass.
- [ ] Research evidence is recorded in `docs/research/auth-rbac.md`.

## Reuse Decision Table

| Need | Reuse | Reason |
|---|---|---|
| Session cookie auth | Laravel Sanctum `statefulApi()` | Native to the installed stack; no token storage. |
| Current user query | TanStack Query `queryOptions` | Same cache path for guard, header, and pages. |
| Role enum | Backed PHP enum | Type-safe and serializes cleanly. |
| Request validation | Laravel FormRequest + shared Zod | Mirrors the existing validation pattern. |
| Auth UI primitives | Existing `components/ui` and Delysa styling | Preserve current visual language. |
| Order privacy | Existing `order-privacy` helpers | Avoid duplicating masking logic. |
| Toasts/forms | Existing form/field patterns | Consistent with sign-in/sign-up. |

## Tasks

### Task 1: Backend role domain

**Files:** enum, migration, model, factory, seeder, resource.

1. Add `Role` enum with `Customer`, `StoreOwner`, `Admin`, `label()`, and `values()`.
2. Add migration `role` string default `customer`, indexed.
3. Cast `role` in `User`; do not add it to `#[Fillable]`.
4. Add factory states and seed customer/owner/admin accounts with non-production defaults.
5. Add `UserResource` returning `id`, `name`, `email`, `role`.
6. Run `php artisan migrate --force` and the focused model/seeder tests.

### Task 2: Backend auth endpoints

**Files:** requests, controller, routes, bootstrap.

1. Normalize/trim email and name in FormRequests.
2. Register: validate, reject duplicate 409, create customer, login, regenerate session, set `auth_started_at`, return 201.
3. Login: validate, `Auth::attempt`, generic 401, regenerate session, set timestamp, return 200.
4. Logout: auth-only 204, invalidate and regenerate CSRF token.
5. Me: auth-only 200 `{user}`.
6. Add `statefulApi()` to `bootstrap/app.php`.
7. Add routes under `/api/v1/auth` with `auth:sanctum` protection where needed.

### Task 3: RBAC and sessions

1. Add `EnsureUserHasRole` alias `role`; return 401/403 JSON.
2. Add `EnsureSessionIsNotExpired` alias `session.lifetime`; 30 days from `auth_started_at`; logout + 401 when exceeded.
3. Configure login limiter: 5/min/IP.
4. Add `SESSION_LIFETIME=10080`, absolute 30 days, secure/lax cookie settings.
5. Make CORS origins env-driven; keep credentials enabled.
6. Align local hosts to `localhost:3000` + `localhost:8000`.

## Risks and Limits

- Cross-site production cookies require same-parent domain; current Vercel + VPS split needs a domain decision.
- Auth route guards are UX only; backend middleware is authoritative.
- Demo orders are not user-scoped; do not claim production order ownership.
- No password reset, email verification, or admin user-management UI in this scope.
